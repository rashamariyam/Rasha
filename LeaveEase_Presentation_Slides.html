1. Project Methodology

Executive Summary & Problem Statement

Addressing structural inefficiencies in legacy collegiate administrative processes

Conventional Paper Processes

  • Manual physical leave application slips easily misplaced or delayed in transit.
  • Paper trails lack real-time auditability and centralized institutional record keeping.
  • Physical signature bottlenecks when faculty or HOD are unavailable.
  • Absence of automated notifications for pending student requests.

Resource Allocation Friction

  • Green Card study slots and discussion rooms booked on manual paper registers.
  • Frequent double-booking and lack of real-time seat availability visibility.
  • Booking past dates or unavailable slots due to absence of dynamic date controls.
  • Classroom schedule conflicts during exam and lecture allocations.

The LeaveEase Solution

  • Zero-paper 2-tier sequential approval engine (Teacher → HOD).
  • Appointment-style calendar: auto current-month lock & past-date suppression.
  • Collision-free O(N) interval scheduling for classrooms and study slots.
  • Accredited tamper-evident institutional leave certificates.

1. Project Methodology

Algorithmic Formulations & Computational Logic

Mathematical and logical algorithms ensuring scheduling integrity and strict verification

1. Collision & Overlap Detection Algorithm

O(N) Complexity
Overlap(S1, E1, S2, E2) = (timeToMin(S1) < timeToMin(E2)) && (timeToMin(E1) > timeToMin(S2))

Guarantees zero double-booking in study slots and classrooms by converting HH:MM to integer minutes elapsed since midnight and executing strict interval overlap evaluations.

2. Multi-Stage Sequential State Machine

State Hierarchy
Pending → [Teacher: Approve/Reject] → [HOD: Approve/Reject] → Final(Approved/Rejected)

Enforces institutional hierarchy. Rejection at teacher tier immediately terminates request with decision note. HOD tier activates only after verified teacher sign-off.

3. Dynamic Calendar Boundary Lock Algorithm

Date Guard
isPrevDisabled(Yv, Mv) <=> (Yv < Ymin) || (Yv == Ymin && Mv <= Mmin - 1)

Locks calendar view to current month, permanently disables prior month navigation, visually suppresses past days, and validates all selected dates on both frontend and backend APIs.

1. Project Methodology

End-to-End System Workflows & User Lifecycles

Structured operational sequence for leave applications and study slot reservations

Student Leave Approval Workflow

  • 1. Student Application: Selects Leave Type, Start & End Date, Reason. Datepicker prevents past-date selection.
  • 2. Date Validation: System checks date logic (End Date ≥ Start Date ≥ Today) and creates Pending request.
  • 3. Faculty Dispatch: Notifications delivered in real time to all department faculty members.
  • 4. Faculty Evaluation: Teacher evaluates reason and duration, either approving or rejecting with remarks.
  • 5. HOD Ratification: Final tier review by Department Head approves request.
  • 6. Accredited Slip: System generates tamper-evident Verified Leave Certificate for attendance regularization.

Green Card Slot Booking Workflow

  • 1. Open Slot Booking: Appointment calendar automatically opens to current month and year.
  • 2. Navigation Constraint: Previous-month button is locked; past dates are disabled.
  • 3. Date Selection: User picks today or future date (library, computer lab, seminar hall).
  • 4. Filtered Slot View: Renders available time slots specifically for selected date.
  • 5. Real-Time Reservation: Single-click booking decrements seat count and reserves seat.
  • 6. Instant Cancellation: Self-service cancellation frees seat for fellow students.

2. Implementation

Technical Innovation: Doctor-Appointment DatePicker

Custom component engineered to prevent past-date selection and lock month navigation

1. Dynamic Month Navigation Lock

  • Previous Month (<) button automatically disabled when viewing current month.
  • User can navigate to future months (>), but cannot navigate prior to current month.
  • When returning from future month, (<) locks immediately upon reaching current month.

2. Visual Past-Date Suppression

  • All dates prior to today (d < today) are visually grayed out with strikethrough.
  • Disabled days have cursor-not-allowed and clicking triggers a strict no-op.
  • Today date is highlighted with navy border; selected date highlighted in solid navy.

3. Full-Stack Integrity Guard

  • Frontend validation catches and rejects any manual date tampering.
  • Client AppContext bookSlot & addLeaveRequest verify d ≥ today in memory.
  • Express backend routes return HTTP 400 Bad Request if past date is submitted.
